# Rossweisse Audio

A website for browsing the shop's tested vintage and modern hi-fi. Customers search and filter the catalog, then send an inquiry; staff manage everything in an admin. There is no checkout yet.

| Part | What it is | Local address |
| --- | --- | --- |
| `web/` | Storefront: SvelteKit 3 + TypeScript, light and dark themes | http://localhost:3001 |
| `cms/` | Staff admin: Strapi 5 (drafts and publishing, media library, inquiries) | http://localhost:1338/admin |
| `db` | PostgreSQL 17 | internal only |
| GitHub Pages demo | Static build of `web/` with sample data, for reviewing the design | not published yet |

All products, brands, prices and policy text in this repo are **invented sample content**.

## Prerequisites

- **Docker Desktop**. On this machine its data lives on G: (`G:\Docker\wsl`).
- **Node.js 22 or 24**, only for checks and tests outside Docker. A portable Node 24 can live in the git-ignored `.tools/node24/` folder:
  ```powershell
  $env:Path = "G:\github-pages\audio-store\.tools\node24;$env:Path"
  ```

## Run the full stack

```powershell
scripts\new-env.ps1                      # .env with fresh secrets
docker compose up -d --build --wait cms  # PostgreSQL + Strapi (first build takes a few minutes)
scripts\seed.ps1                         # sample catalog + storefront tokens into .env, starts web
```

Then create the first administrator at http://localhost:1338/admin and open the storefront at http://localhost:3001.

## Work on the storefront without Docker

Without `STRAPI_URL`, the storefront serves the bundled sample catalog:

```powershell
cd web
npm ci
npm run dev            # http://localhost:5173
```

## Checks and tests

```powershell
cd web
npm run check          # TypeScript / svelte-check
npm run lint           # prettier + eslint
npm test               # unit tests
npm run e2e:install    # one-time: Chromium into ..\.tools\ms-playwright
npm run test:e2e       # browser tests against the Node build (sample data)
npm run test:e2e:demo  # the same against the static demo, under /rossweisse-audio/
npm run test:e2e:stack # the same against the running Docker stack, including a real inquiry

cd ..\cms
npm ci
npm run typecheck
npm test               # admin form layouts match the schemas
```

## The GitHub Pages demo

```powershell
cd web
npm run build:demo     # static site in web/build-demo/
npm run preview:demo   # http://localhost:4174/rossweisse-audio/ (served the way GitHub Pages does)
```

`.github/workflows/demo.yml` checks the CMS, tests and builds the demo, and publishes it on every push to `main`. To turn it on:

1. Create the GitHub repository (named `rossweisse-audio` to match the local preview) and push.
2. In the repository, open **Settings → Pages** and set *Source* to **GitHub Actions**.

The demo is public. A banner on every page says it is sample content, and its forms don't send anything.

## Sample content

`web/src/lib/demo/content.json` and the placeholder illustrations in `web/static/demo/` are generated by `npm run demo:generate` from `web/scripts/demo-content.js`. Edit that script, not the JSON. The CMS seed (`cms/scripts/seed.js`) loads the same file, so the demo and the CMS match.
